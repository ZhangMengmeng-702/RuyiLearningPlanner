## 2. 路由与页面

| 路由 | 页面组件 | 功能说明 |
|:---|:---|:---|
| `/learn` | `LearnChatPage` | AI 对话生成学习计划（画像采集 + SSE 流式输出） |
| `/learn/plan` | `PlanViewPage` | 计划看板（里程碑卡片 + 每日任务展开） |
| `/learn/plan/:planId` | `PlanViewPage` | 指定计划 ID 的看板 |
| `/learn/today` | `TodayPage` | 今日任务 + 打卡反馈 + 进度统计 |
| `*` | 重定向 → `/learn` | 其他路由自动跳转 |

所有页面使用 `React.lazy` 懒加载，配合 `<Suspense>` 显示加载中回退。

### 页面间导航

```
对话规划 (LearnChatPage)
    │  用户输入 → SSE 生成计划 → 点击"计划看板"链接
    ▼
计划看板 (PlanViewPage)
    │  查看每日任务 → 点击"今日任务"侧边栏
    ▼
今日任务 (TodayPage)
    │  完成任务 → 提交反馈打卡
    ▼
对话规划 (LearnChatPage)  ← 可继续调整计划
```

## 4. Hooks

### 4.1 `useLearningChat(userId: string)`

```typescript
// 返回值
{
  messages: ChatMessage[];         // 消息列表
  setMessages: Dispatch<SetStateAction<ChatMessage[]>>;
  loading: boolean;                // 是否正在请求
  plan: StudyPlan | null;          // 生成的计划（SSE 推送）
  setPlan: Dispatch<SetStateAction<StudyPlan | null>>;
  sendMessage: (userMsg: string, useMock?: boolean) => Promise<void>;
}
```

- 调用 `apiPostSSE('/api/v1/learn/chat', ...)` 发起 SSE 流式请求
- `useMock=true` 时走本地 mock 数据（不依赖后端）
- 支持 `AbortController` 取消请求

### 4.2 `usePlan(planId: string)`

```typescript
// 返回值
{
  plan: StudyPlan | null;
  loading: boolean;
  error: string;
}
```

- 调用 `apiGet('/api/v1/learn/plan/{planId}')`
- 自动处理 loading/error 状态

### 4.3 `useProgress(userId: string, planId: string)`

```typescript
// 返回值
{
  stats: ProgressStats | null;
  loading: boolean;
  checkin: (payload: CheckinPayload) => Promise<void>;
}
```

- 调用 `apiGet('/api/v1/progress/stats/{userId}?plan_id={planId}')` 获取统计
- 调用 `apiPost('/api/v1/progress/checkin', payload)` 提交打卡
- 打卡成功后自动刷新统计

## 5. API 接口定义

> 前端通过 `services/api.ts` 统一封装请求，`API_BASE` 固定为 `http://localhost:8000`。
> Vite 开发服务器也配置了代理：`/api` → `http://127.0.0.1:8000`。

### 5.1 健康检查

```
GET /health
Response: { "status": "ok" }
```

### 5.2 画像管理

```
GET /api/v1/profile/{user_id}
Response: {
  "user_id": "string",
  "exists": boolean,
  "profile": {
    "goal": "string",
    "current_level": "string",      // "beginner" | "intermediate" | "advanced"
    "hours_per_week": number,
    "preference": "string",         // "video" | "reading" | "hands-on"
    "known_topics": string[],
    "is_complete": boolean
  } | null
}

POST /api/v1/profile/{user_id}
Body: {
  "goal": "string",
  "current_level": "string",
  "hours_per_week": number,
  "preference": "string"
}
Response: { "success": true }
```

### 5.3 学习对话（SSE 流式）

```
POST /api/v1/learn/chat
Body: {
  "user_id": "string",
  "message": "string",
  "session_id": "string"
}
Response: SSE 流式数据，每行格式：
  data: {"event": "token", "data": "正在生成..."}
  data: {"event": "plan", "data": { ... StudyPlan JSON ... }}
```

**SSE 事件类型：**
- `event: "token"` — 文本 token，`data` 为字符串片段，前端逐块拼接
- `event: "plan"` — 计划生成完成，`data` 为完整 `StudyPlan` 对象

### 5.4 计划管理

```
GET /api/v1/learn/plan/{plan_id}
Response: StudyPlan 完整对象
```

### 5.5 打卡与进度

```
POST /api/v1/progress/checkin
Body: {
  "user_id": "string",
  "plan_id": "string",
  "day": number,
  "tasks_completed": string[],     // 已完成任务 ID 列表
  "difficulty_rating": number,     // 1-5
  "completion_pct": number,        // 0-100
  "time_spent_hours": number,
  "feedback_text": "string"
}
Response: { "success": true }

GET /api/v1/progress/stats/{user_id}?plan_id={plan_id}
Response: ProgressStats
```

## 6. 数据模型 (TypeScript)

> 以下类型定义在 `src/types/index.ts`，与后端返回的 JSON 结构严格对应。

### 6.1 StudyPlan（学习计划）

```typescript
interface StudyPlan {
  plan_id: string;                 // 计划唯一 ID
  goal: string;                    // 学习目标
  user_id: string;                 // 所属用户
  total_weeks: number;             // 总周数
  created_at: string;              // ISO 日期
  milestones: Milestone[];         // 里程碑列表
  daily_tasks: DailyTask[];        // 每日任务列表
  prerequisite_check: PrerequisiteCheck;  // 前置依赖检查
  evaluation?: PlanEvaluation;     // 质量评估（可选）
  adjusted?: boolean;              // 是否被调整过
  adjust_reason?: string;          // 调整原因
}
```

### 6.2 Milestone（里程碑 / 阶段）

```typescript
interface Milestone {
  week_start: number;              // 起始周（1-based）
  week_end: number;                // 结束周
  phase: string;                   // 阶段名称
  description: string;             // 阶段描述
  objectives: string[];            // 学习目标列表
  task_count: number;              // 任务数量
  difficulty: 1 | 2 | 3;          // 难度等级
}
```

### 6.3 DailyTask（每日任务）

```typescript
interface DailyTask {
  day: number;                     // 第几天（1-based）
  week: number;                    // 第几周
  tasks: TaskItem[];               // 该天的任务列表
}

interface TaskItem {
  id: string;                      // 任务唯一 ID
  title: string;                   // 任务标题
  description?: string;            // 任务描述
  est_hours: number;               // 预计耗时（小时）
  resource_url?: string;           // 学习资源链接
  resource_title?: string;         // 资源标题
  completed?: boolean;             // 是否已完成
}
```

### 6.4 PrerequisiteCheck（前置依赖检查）

```typescript
interface PrerequisiteCheck {
  status: 'passed' | 'warning' | 'failed';
  details: {
    chapter: string;
    prerequisites: string[];
    status: string;                // "covered" | "missing"
  }[];
  warnings: string[];
}
```

### 6.5 PlanEvaluation（计划质量评估）

```typescript
interface PlanEvaluation {
  score: number;                   // 评分 1-10
  issues: string[];                // 存在的问题
  suggestions: string[];           // 改进建议
}
```

### 6.6 ProgressStats（进度统计）

```typescript
interface ProgressStats {
  total_days: number;              // 已完成天数
  completed_days: number;          // 高质量完成天数（≥80%）
  streak: number;                  // 连续打卡天数
  avg_completion_pct: number;      // 平均完成率
  avg_difficulty: number;          // 平均难度
  total_hours: number;             // 总学习时长
  checkins: {                      // 每日打卡记录
    day: number;
    date: string;
    difficulty: number;
    completion: number;
    hours: number;
    feedback: string;
  }[];
}
```

### 6.7 CheckinPayload（打卡请求）

```typescript
interface CheckinPayload {
  user_id: string;
  plan_id: string;
  day: number;
  tasks_completed: string[];       // 任务 ID 列表

  completion_pct: number;          // 0-100
  time_spent_hours: number;
  feedback_text: string;
```

### 6.8 ProfileData（用户画像）

## 7. 与后端整合要点

### 7.1 约定的 API 前缀

- 前端所有请求通过 `services/api.ts` 发出，默认前缀 `http://localhost:8000`
- 开发环境 Vite 代理配置（`vite.config.ts`）：
  ```
  /api → http://127.0.0.1:8000
  ```
- 生产环境需修改 `API_BASE` 或通过代理转发

### 7.2 StudyPlan 数据结构要求

`StudyPlan` 是最核心的数据结构，**所有字段必须齐全**，否则前端页面可能出现空白。特别注意：

- `milestones[].week_start` / `week_end` 用于前端计算每日任务归属
- `daily_tasks[].week` 必须与 `milestones[].week_start~week_end` 范围一致，否则任务无法正确展示在对应里程碑下
- `daily_tasks[].tasks[].id` 必须唯一，前端用 `id` 追踪选中状态
- `daily_tasks` 可以为空数组，前端会显示"暂无每日任务"提示
- `prerequisite_check` 必须提供，即使为空对象（`{status:'passed', details:[], warnings:[]}`）

### 7.3 SSE 流式约定

- 后端必须按行输出，每行格式：`data: {json}\n\n`
- 不要包含 `event:` 行，前端按 `event` 字段值区分
- 先发送 `event: "token"` 事件，最后发送 `event: "plan"` 事件
- 如果只生成计划不需要流式文本，可以只发一个 `event: "plan"` 事件

### 7.4 错误处理

- 前端对每个 API 调用都有 try-catch 或 `.catch()` 处理
- 网络错误时前端会显示"连接失败：请确保后端服务已启动"
- 后端应返回合适的 HTTP 状态码（4xx/5xx），前端会读取 `resp.ok` 判断

### 7.5 画像与计划的关联

- 前端首次加载 `/learn` 时会调用 `GET /api/v1/profile/{user_id}` 检查画像完整性
- 画像不完整时弹出采集表单，用户填写后 `POST /api/v1/profile/{user_id}`
- 画像保存成功后，用户才能发送学习目标生成计划

## 8. Mock 模式

前端在 `useLearningChat` hook 中内置了 Mock 模式，用于后端不可用时独立开发测试。

### 启用方式

对话页输入框下方有一个复选框 **"Mock 模式（后端不可用时使用）"**，勾选后发送消息会走本地 mock 数据。

### Mock 数据内容

- 模拟 SSE 流式输出（逐字 30ms 间隔）
- 生成一个 12 周、6 个里程碑的假计划
- 包含 3 条示例每日任务

### 与真接口的切换

- 取消勾选复选框 → 恢复正常 API 调用
- 无需修改代码即可在 Mock 和真接口间切换
- 适合前端独立开发 UI 和交互，后端联调时关闭 Mock 即可
