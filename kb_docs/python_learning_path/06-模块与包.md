## 一、模块回顾与深入

### 1.1 什么是模块

模块（Module）就是一个 `.py` 文件，里面定义了函数、类、变量等。使用模块可以：
- 代码复用：写一次，多处使用
- 命名空间：不同模块可以有同名函数，互不冲突
- 组织代码：把相关功能放在一起，结构清晰

### 1.2 模块的导入方式

```python
# 方式一：导入整个模块
import math
print(math.sqrt(16))  # 4.0

# 方式二：导入模块中的特定内容
from math import sqrt, pi
print(sqrt(16))  # 4.0
print(pi)        # 3.14159...

# 方式三：导入模块并起别名
import numpy as np
print(np.array([1, 2, 3]))

# 方式四：导入模块中所有内容（不推荐，容易名字冲突）
from math import *
```

### 1.3 模块的搜索路径

当你 `import math` 时，Python 会从这些地方找 `math.py`：

1. **当前目录** — 脚本运行的目录
2. **PYTHONPATH** — 环境变量中配置的目录
3. **标准库目录** — Python 安装目录下的 Lib
4. **第三方包目录** — site-packages

查看搜索路径：
```python
import sys
print(sys.path)
```

### 1.4 `__name__` 变量

每个模块都有一个 `__name__` 变量：
- 如果模块是**直接运行**的，`__name__ == "__main__"`
- 如果模块是**被导入**的，`__name__ == 模块名`

经典用法 — 让模块既可以被导入，又可以直接运行：
```python
# my_module.py
def add(a, b):
    return a + b

def main():
    print("测试：1 + 2 =", add(1, 2))

if __name__ == "__main__":
    main()
```
- 直接运行 `python my_module.py` → 执行 `main()`
- 被其他文件 `import` → 只定义函数，不执行 `main()`

## 二、包（Package）

### 2.1 什么是包

包（Package）就是一个**包含 `__init__.py` 文件的目录**。包里面可以有多个模块，也可以有子包。

```
my_project/
├── main.py
├── utils/                    # 这是一个包
│   ├── __init__.py           # 包的初始化文件
│   ├── string_utils.py       # 模块1
│   └── math_utils.py         # 模块2
└── data/                     # 这也是一个包
    ├── __init__.py
    ├── loader.py
    └── processor.py
```

### 2.2 `__init__.py` 的作用

`__init__.py` 标志着这个目录是一个 Python 包。它可以是空文件，也可以做这些事：

**1. 控制导入内容**
```python
# utils/__init__.py
from .string_utils import to_upper, to_lower
from .math_utils import add, multiply

__all__ = ["to_upper", "to_lower", "add", "multiply"]
```
这样 `from utils import *` 就会导入 `__all__` 里的内容。

**2. 执行包级别的初始化**
```python
# utils/__init__.py
print("utils 包被导入了")
VERSION = "1.0.0"
```

**3. 简化导入路径**
```python
# 原本需要：from utils.string_utils import to_upper
# 在 __init__.py 里导入后，可以：
from utils import to_upper
```

### 2.3 绝对导入 vs 相对导入

**绝对导入**（推荐，清晰明确）：
```python
# main.py 中
from utils.string_utils import to_upper
from utils.math_utils import add
from data.loader import load_data
```

**相对导入**（在包内部使用，用 `.` 和 `..`）：
```python
# utils/math_utils.py 中
from .string_utils import to_upper   # . 表示当前包
```

```python
# data/processor.py 中
from ..utils.math_utils import add   # .. 表示父包
```

> **建议**：新手多用绝对导入，不容易出错。相对导入适合比较复杂的项目。

### 2.4 子包

包里面还可以有包：
```
my_project/
└── utils/
    ├── __init__.py
    ├── string/           # 子包
    │   ├── __init__.py
    │   ├── case.py
    │   └── format.py
    └── math/             # 子包
        ├── __init__.py
        ├── basic.py
        └── stats.py
```

导入方式：
```python
from utils.string.case import to_upper
from utils.math.stats import mean
```

## 三、pip 包管理

### 3.1 什么是 pip

pip 是 Python 的包管理器，用来安装、卸载、管理第三方包。Python 3.4+ 自带 pip。

检查 pip 版本：
```bash
pip --version
# 或
python -m pip --version
```

### 3.2 常用 pip 命令

| 命令 | 作用 | 示例 |
|------|------|------|
| `pip install 包名` | 安装包 | `pip install pandas` |
| `pip install 包名==版本` | 安装指定版本 | `pip install pandas==2.0.0` |
| `pip install 包名>=版本` | 安装最低版本 | `pip install pandas>=1.5.0` |
| `pip uninstall 包名` | 卸载包 | `pip uninstall pandas` |
| `pip list` | 列出已安装的包 | `pip list` |
| `pip freeze` | 以 requirements 格式列出 | `pip freeze` |
| `pip show 包名` | 查看包信息 | `pip show pandas` |
| `pip install -r requirements.txt` | 从文件批量安装 | `pip install -r requirements.txt` |
| `pip install --upgrade 包名` | 升级包 | `pip install --upgrade pandas` |

### 3.3 requirements.txt

项目依赖清单，方便别人一键安装所有依赖：

**生成 requirements.txt**：
```bash
pip freeze > requirements.txt
```

**文件内容示例**：
```
numpy==1.24.0
pandas==2.0.0
matplotlib==3.7.0
seaborn==0.12.2
```

**别人拿到项目后安装依赖**：
```bash
pip install -r requirements.txt
```

### 3.4 国内镜像源

默认从 PyPI 下载可能很慢，国内推荐用镜像源：

**临时使用**：
```bash
pip install pandas -i https://pypi.tuna.tsinghua.edu.cn/simple
```

**常用镜像源**：
| 源 | URL |
|----|-----|
| 清华大学 | https://pypi.tuna.tsinghua.edu.cn/simple |
| 阿里云 | https://mirrors.aliyun.com/pypi/simple |
| 中科大 | https://pypi.mirrors.ustc.edu.cn/simple |

**永久配置**：
```bash
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

## 四、虚拟环境

### 4.1 为什么需要虚拟环境

问题场景：
- 项目 A 需要 pandas 1.x
- 项目 B 需要 pandas 2.x
- 都装在系统 Python 里会冲突

**虚拟环境**：每个项目一个独立的 Python 环境，互不干扰。

### 4.2 venv（Python 自带）

Python 3.3+ 自带 `venv` 模块，不需要额外安装。

**创建虚拟环境**：
```bash
# 进入项目目录
cd my_project

# 创建虚拟环境（env 是环境名，也可以叫 venv）
python -m venv env
```

创建后会生成一个 `env/` 目录：
```
my_project/
├── env/              # 虚拟环境目录
│   ├── Scripts/      # Windows: 可执行文件
│   ├── Lib/          # 库文件
│   └── ...
└── main.py
```

**激活虚拟环境**：

Windows (PowerShell)：
```bash
.\env\Scripts\Activate.ps1
# 激活后，命令行前面会出现 (env)
```

Windows (CMD)：
```bash
env\Scripts\activate.bat
```

Mac/Linux：
```bash
source env/bin/activate
```

**在虚拟环境中安装包**：
```bash
# 确保前面有 (env)
(env) pip install pandas numpy matplotlib
```

**退出虚拟环境**：
```bash
deactivate
```

### 4.3 虚拟环境最佳实践

1. **环境目录不要提交到 Git**
   - 把 `env/`、`venv/` 加入 `.gitignore`
   - 只提交 `requirements.txt`

2. **每个项目一个虚拟环境**
   - 项目之间完全隔离，版本不冲突

3. **生成依赖清单**
   ```bash
   pip freeze > requirements.txt
   ```

4. **新人搭建项目**
   ```bash
   # 克隆代码后
   python -m venv env
   # 激活
   pip install -r requirements.txt
   ```

### 4.4 其他虚拟环境工具

| 工具 | 特点 | 适用场景 |
|------|------|----------|
| venv | Python 自带，零安装 | 新手、简单项目 |
| virtualenv | venv 的增强版 | 老版本 Python |
| conda | 跨语言，支持非 Python 包 | 数据科学、多环境管理 |
| poetry | 依赖管理 + 打包 | 现代 Python 项目 |
| pipenv | Pipfile + 虚拟环境 | 替代 pip + venv |

> **建议**：新手先用 `venv`，等有需要再学其他的。

## 五、包的发布与安装（了解）

### 5.1 包的目录结构

如果你想把自己的代码打包发布到 PyPI：

```
my_package/
├── my_package/
│   ├── __init__.py
│   ├── module1.py
│   └── module2.py
├── tests/
├── README.md
├── pyproject.toml
└── LICENSE
```

### 5.2 常用的包分布格式

| 格式 | 说明 |
|------|------|
| 源码包（sdist） | `.tar.gz`，包含源码，需要编译 |
| wheel 包 | `.whl`，预编译，安装更快 |

安装时 pip 会优先用 wheel 包。

## 六、常见问题

**Q**: 导入模块时出现 `ModuleNotFoundError` 怎么办？
**A**: 检查三个点：① 包/模块名是否拼错 ② 有没有安装（`pip list` 看看） ③ 是不是在虚拟环境里但装到系统 Python 了

**Q**: `import` 和 `from...import` 哪个好？
**A**: 各有优劣。`import math` 更清晰（知道函数来自哪），`from math import sqrt` 更简洁。小项目随便用，大项目推荐用 `import` 避免名字冲突。

**Q**: 相对导入总是报错怎么办？
**A**: 新手先别用相对导入，用绝对导入更简单。如果一定要用，确保你的脚本是作为模块运行的（`python -m 包名.模块名`），而不是直接运行脚本。

**Q**: 虚拟环境里装了包，但运行时还是找不到？
**A**: 先看看命令行前面有没有 `(env)`，没有就是没激活。另外，VS Code 里要选择正确的 Python 解释器（Ctrl+Shift+P → Python: Select Interpreter）。
